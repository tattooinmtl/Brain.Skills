# MNNV Brain Control — `/skill-brain <verb>`

The brain is a zero-dep Node server in
`C:\Users\ThePa\.minimax\plugins\brain\`. Port `6789`. The launcher
(`bin/brain.js`) covers server lifecycle; the CLI (`bin/brain-cli.js`)
covers one-shot API calls; this skill is the *interface* — pick the
right verb and run the matching command.

## Quick-reference

| Verb               | What it does                                              | Goes through                              |
|--------------------|-----------------------------------------------------------|-------------------------------------------|
| `start`            | Boot server (if down) + open `neural.html`                | `bin/brain.js start`                      |
| `stop`             | Kill the server                                           | `bin/brain.js stop`                       |
| `restart`          | `stop` + `start` + open view                             | both                                      |
| `status`           | Health: pid, version, atoms, edges, uptime                | `/api/health`                             |
| `open <page>`      | Open a brain page in the default browser                  | direct `Start-Process`                    |
| `help` / `-h`      | Print this table                                          | (this section)                            |
| `remember <text>`  | Create a `chatmem/fact` atom (auto-tags tech words)       | `bin/brain.js remember`                   |
| `search <q>`       | Vector search over atoms, top 8                          | `bin/brain.js search`                     |
| `pulse <text>`     | Log a `tool` activity event (lightweight)                 | `bin/brain-cli.js pulse`                  |
| `think`            | Fire `thinking` start → wait → end (pulses the brain)     | `bin/brain-cli.js thinking start\|end`     |
| `speak <text>`     | Create a `voice` chatmem atom + vocalize                  | `bin/brain-cli.js speak`                  |
| `log`              | Tail the last 200 lines of `data/brain.log`               | `bin/brain.js log`                        |
| `install`          | Drop auto-start shortcut into Windows Startup             | `bin/brain.js install`                    |
| `reuse <id>`       | Mark a skill reused → bumps fused-atom weight             | `bin/brain-cli.js reuse`                  |
| `code <a> <file>`  | Log a code edit (`edit`/`create`/`delete`) with `--skill` | `bin/brain-cli.js code`                   |
| `activity`         | Show the last 20 activity events                          | `GET /api/activity?n=20`                  |
| `inbox <json>`     | Append a raw event to the inbox log                       | `bin/brain-cli.js inbox`                  |

Pages accepted by `open`: `neural` (default), `wiki`, `wiki-index`,
`logs`, `evolve`, `quakes`, `index`. Any other page is treated as a
relative path under the brain root (`/foo.html`).

## Procedure

### 1. Identify the verb

Strip the leading `/skill-brain ` (or the natural-language prefix
"brain", "MNNV") and read what comes after. If the input has no
recognizable verb, default to `help`. If the input is just
`/skill-brain`, default to `start`.

### 2. Branch on the verb

Run the matching sub-procedure from the table below. Most are one
PowerShell line; none require LLM reasoning.

#### `start` — boot and open the view

```powershell
$ErrorActionPreference = 'Stop'
$port = Test-NetConnection -ComputerName 127.0.0.1 -Port 6789 -InformationLevel Quiet -WarningAction SilentlyContinue
if (-not $port) {
  node "C:\Users\ThePa\.minimax\plugins\brain\bin\brain.js" start
  Start-Sleep -Seconds 1
}
$h = (Invoke-WebRequest -UseBasicParsing -Uri "http://127.0.0.1:6789/api/health" -TimeoutSec 3).Content | ConvertFrom-Json
Start-Process "http://127.0.0.1:6789/neural.html"
"MNNV v$($h.version) — $($h.atoms) atoms, $($h.edges) edges, port 6789, uptime $($h.uptime_s)s"
```

Reply: `MNNV v0.2.0 — 62 atoms, 158 edges, port 6789, uptime 1s`. If
the brain was already up, prefix with `already up — `.

#### `stop`

## Failure handling

- **Port 6789 busy from a non-brain process:** tell the user the
  port is in use; do not auto-kill. They can `netstat -ano | findstr
  :6789` to find the offender.
- **Stale pid file (port free, no process):** delete
  `data/brain.pid` and re-run `start`.
- **`/api/health` returns an error after a successful start:** read
  the last 30 lines of `data/brain.log` and surface the first
  stack-trace line.
- **`remember` / `search` reports "no results":** confirm the brain
  is up; if yes, suggest the user run `pulse` once to trigger
  index refresh, then retry.
- **Unknown verb:** run `help` and ask the user to pick a verb. Do
  not guess.

## What this skill does NOT do

- It does not edit atoms, propose memories, or run the chat agent.
  Use `self-learning-brain` for that.
- It does not install or upgrade the plugin itself. Use
  `self-learning-brain` and the recipe cards in
  `knowledge/skills/recipe-*.md` to bootstrap a fresh install.
- It does not change the port. Port 6789 is fixed by the launcher
  and the brain's SSE clients.
