# CLAP Dev Skill

Build a Windows CLAP audio plugin (Effect and/or Instrument) from a plain-language
description or a `plugin_spec.yaml` — all the way to a validated `.clap` artifact.

**Pipeline overview:**

```text
User description
  → [1] Capture spec (plugin_spec.yaml)
  → [2] Generate NIH-plug/Rust skeleton
  → [3] Build: cargo xtask bundle --release
  → [4] Validate: clap-validator validate
  → [5] Install hint (Windows path)
```

---

## Step 1 — Capture the Spec

If the user has not provided a `plugin_spec.yaml`, ask for the minimum needed and
write it for them. Required fields:

```yaml
name: "MyPlugin"
vendor: "YourVendor"
url: "https://example.invalid"
email: "support@example.invalid"
clap_id: "com.yourvendor.myplugin"   # must be globally unique, reverse-domain style
type: "effect"                        # effect | instrument | both
version: "0.1.0"

io:
  audio_in: 2        # 0 is valid for instruments
  audio_out: 2
  note_in: true      # true for instruments; false for pure effects
  note_out: false

params:
  - id: "gain"
    name: "Gain"
    kind: "float"    # float | int | bool | enum
    min: -24.0
    max: 24.0
    default: 0.0
```

**type: "both"** means two plugin descriptors share one binary (one CLAP factory
lists both). Generate two `impl Plugin` structs in `src/lib.rs` and call
`nih_export_clap!(EffectPlugin, InstrumentPlugin)`.

**Validation rules to check before generating:**

- `clap_id` must contain at least one dot (reverse-domain format)
- `audio_out` must be ≥ 1
- `params[].kind == "float"` or `"int"` requires `min` and `max`
- `kind == "enum"` requires an `enum_values: [...]` list

## Step 2 — Generate NIH-plug / Rust Skeleton

### Repository bootstrap (first time only)

```bash
# Use the official cookiecutter template
cargo install cargo-generate
cargo generate --git https://github.com/robbert-vdh/nih-plug-template --name <plugin-name>
cd <plugin-name>
```

Then overwrite `src/lib.rs` with the generated skeleton below.

### Skeleton template (effect)

```rust
    params: Arc<{{PluginName}}Params>,
}

pub struct {{PluginName}}Params {
    #[id = "gain"]
    pub gain: FloatParam,
    // Add more params here
}

impl Default for {{PluginName}} {
    fn default() -> Self {
        Self {
            params: Arc::new({{PluginName}}Params {
                gain: FloatParam::new(
                    "Gain",
                    0.0,
                    FloatRange::Linear { min: -24.0, max: 24.0 },
                ),
            }),
        }
    }
}

impl Plugin for {{PluginName}} {
    const NAME: &'static str = "{{name}}";
    const VENDOR: &'static str = "{{vendor}}";
    const URL: &'static str = "{{url}}";
    const EMAIL: &'static str = "{{email}}";
    const VERSION: &'static str = "{{version}}";
    const CLAP_ID: &'static str = "{{clap_id}}";

        main_input_channels: NonZeroU32::new(2),
        main_output_channels: NonZeroU32::new(2),
        ..AudioIOLayout::const_default()
    }];

    type SysExMessage = ();
    type BackgroundTask = ();

    fn params(&self) -> Arc<dyn Params> {
        self.params.clone()
    }

    fn process(
        &mut self,
        buffer: &mut Buffer,
        _aux: &mut AuxBuffers,
        _context: &mut impl ProcessContext<Self>,
    ) -> ProcessStatus {
        // TODO: implement DSP here
        // Example: pass-through with gain
        for channel_samples in buffer.iter_samples() {
            let gain_db = self.params.gain.smoothed.next();
            let gain_linear = util::db_to_gain(gain_db);

}

nih_export_clap!({{PluginName}});
```

### Instrument additions

For `type: instrument`, add to the `Plugin` impl:

```rust
const MIDI_INPUT: MidiConfig = MidiConfig::Basic;
```

And in `process()`, iterate note events:

```rust
while let Some(event) = context.next_event() {
    match event {
        NoteEvent::NoteOn { note, velocity, .. } => { /* start voice */ }
        NoteEvent::NoteOff { note, .. }          => { /* stop voice  */ }
        _ => {}
    }
}
```

### Both in one binary

```rust
nih_export_clap!(EffectPlugin, InstrumentPlugin);
```

Both descriptors are listed by the same CLAP factory. Give each a distinct
`const NAME` and `const CLAP_ID`.

## Step 3 — Build

```bash
cargo xtask bundle <plugin-name> --release
```

The bundler reads which formats are exported and produces the correct output
structure. The `.clap` file appears under `target/bundled/`.

**If `cargo xtask bundle` fails** (xtask not present in template):

```bash
cargo build --release
# then rename/copy:
copy target\release\<plugin_name>.dll target\bundled\<PluginName>.clap
```

**Windows-specific note:** enable long paths if the build fails with path errors:

```powershell
reg add "HKLM\SYSTEM\CurrentControlSet\Control\FileSystem" /v LongPathsEnabled /t REG_DWORD /d 1 /f
```

## Step 4 — Validate

```bash
clap-validator validate target\bundled\<PluginName>.clap --only-failed
```

Install clap-validator if missing:

```bash
cargo install --git https://github.com/free-audio/clap-validator --locked
```

**Common failures and fixes:**

| Validator error | Likely cause | Fix |
| --- | --- | --- |
| `clap_entry not found` | Wrong export macro | Confirm `nih_export_clap!(...)` is present |
| `Plugin did not process audio` | Empty `process()` | Return `ProcessStatus::Normal`, even pass-through is fine |
| `State save/load mismatch` | No state impl | Add `#[persist = "key"]` to params or implement `State` |
| `Invalid CLAP ID` | Missing dot in id | Use reverse-domain: `com.vendor.plugin` |

Run `clap-info` for metadata inspection:

```bash
clap-info target\bundled\<PluginName>.clap
```

**Definition of Done:**

- ✅ `clap-validator validate` exits 0 (or `--only-failed` shows nothing)
- ✅ Binary exports only `clap_entry` (self-contained)
- ✅ `.clap` file exists in `target\bundled\`

## Step 5 — Install Hint (Windows)

```powershell
# Copy to system-wide CLAP folder (requires admin)
$dest = "C:\Program Files\Common Files\CLAP\"
New-Item -ItemType Directory -Force -Path $dest
Copy-Item "target\bundled\<PluginName>.clap" -Destination $dest
```

Then rescan plugins in your DAW. Most CLAP hosts (Bitwig, Reaper, Waveform) scan
`C:\Program Files\Common Files\CLAP\` automatically.

## Iteration Loop

If the build or validator fails, apply this loop:

1. Read the error output carefully
2. Make the **minimal** change that fixes the reported issue
3. Re-run `cargo xtask bundle --release`
4. Re-run `clap-validator validate --only-failed`
5. Repeat until green

Never change `plugin_spec.yaml` to work around a code issue — keep the spec as the
single source of truth.

After each successful validation, report:

1. Artifact path
2. Validator status (pass/fail + any warnings)
3. The 3 most important log lines if there were issues
