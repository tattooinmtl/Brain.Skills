| Layer | Choice |

### Step 2: Database & content model

Implement schema from [content-schema.md](references/content-schema.md). Minimum tables:

- `Business` — tenant root (name, slug, vertical, timezone)
- `SiteContent` — `draftJson`, `publishedJson`, `publishedAt`
- `Lead` — form submissions with status pipeline
- `MediaAsset` — uploaded/generated files
- `AiChangeLog` — prompt, patch, appliedBy, timestamp
- `User` — owner/staff for admin

**Rule:** Public routes read **only** `publishedJson`. Admin edits **draft**; explicit Publish action copies draft → published.

### Step 3: Seed content

1. Copy [templates/site-content.json](templates/site-content.json)
2. Customize using [vertical-playbooks.md](references/vertical-playbooks.md)
3. Run Prisma seed — never ship Lorem ipsum on public pages
4. Generate real media via `frontend-dev` scripts (confirm with user before API spend)

### Step 4: Public website

Build all required pages per [public-site-pages.md](references/public-site-pages.md):

| Page | Purpose |
|------|---------|
| `/` | Hero, trust badges, services preview, social proof, CTA |
| `/services` | Service list with benefits + pricing hints |
| `/service-areas` | Geo coverage + map embed placeholder |
| `/about` | Story, licenses, insurance, team |
| `/gallery` or `/projects` | Before/after (vertical-dependent) |
| `/reviews` | Testimonials (schema-ready) |
| `/faq` | Objections + SEO |
| `/contact` | Form + NAP (name, address, phone) |
| `/privacy`, `/terms` | Legal stubs |

**Conversion requirements:**

- Sticky phone + "Free Quote" on mobile
- Primary CTA above fold on every page
- Lead form on `/contact` + **inline quote form** on home and service pages
- Click-to-call `tel:` links
- LocalBusiness + FAQ JSON-LD ([seo-local.md](references/seo-local.md))

Follow `frontend-dev` for design quality (no Inter, no purple AI gradients, real assets only).

### Step 5: Lead generation system

Implement per [lead-forms.md](references/lead-forms.md):

- Form types: `quote`, `contact`, `callback`, `emergency` (if vertical supports)
- Server action or `POST /api/leads` with Zod validation
- Spam: honeypot + IP rate limit; Turnstile if `TURNSTILE_SECRET` set
- Store lead → notify owner email → optional SMS webhook stub
- Admin: list, filter, status (`new` → `contacted` → `quoted` → `won` / `lost`), notes, export CSV

### Step 6: Admin dashboard

Implement per [admin-dashboard.md](references/admin-dashboard.md):

| Area | Capabilities |
|------|----------------|
| **Overview** | New leads (7d), conversion funnel counts, quick actions |
| **Leads** | Table, detail drawer, status, internal notes |
| **Content** | Section editors bound to `SiteContent` draft (hero, services, testimonials, hours, areas, SEO) |
| **Media** | Upload, assign to sections |
| **Publish** | Preview draft vs live → confirm publish |
| **AI Assistant** | Chat panel — see Step 7 |
| **Settings** | Business profile, notification emails, users |

Use role `owner` | `staff` — staff cannot delete business or manage users ([security-rbac.md](references/security-rbac.md)).

### Step 7: AI site editor

Implement per [ai-site-editor.md](references/ai-site-editor.md):

```
User message → load draft SiteContent + vertical context
            → LLM returns SiteContentPatch (JSON, no freeform HTML)
            → Zod validate patch
            → Show diff preview in admin UI
            → User clicks Apply → merge into draftJson → log AiChangeLog
            → User publishes when ready
```

**Never** let AI write arbitrary React/HTML directly. **Always** patch structured content only.

Example user intents the AI must handle:

- "Change headline to mention 24/7 emergency service"
- "Add deck staining to services"
- "Make testimonials sound more friendly"
- "Update service areas to include Round Rock"

### Step 8: Integration & hardening

Apply `fullstack-dev` checklist: typed errors, health routes, CORS, env validation, graceful shutdown if split server.

Run [deployment.md](references/deployment.md) smoke tests before handoff.

### Step 9: Handoff

Deliver to user:

1. **Run commands** — `npm install`, `npx prisma migrate dev`, `npm run dev`
2. **Default admin** — how to create first user (seed or signup route)
3. **Env vars** — from `.env.example`
4. **What's live** — page list, form endpoints, admin URL `/admin`
5. **Next steps** — domain, Google Business Profile, analytics, Turnstile, S3

Content CMS
- [ ] Edit draft → preview → publish updates public site
- [ ] Public never reads draftJson

AI editor
- [ ] Chat returns valid patch only (invalid patch shows error, no apply)
- [ ] Apply requires explicit user confirmation
- [ ] AiChangeLog row created per apply

Security
- [ ] /admin and /api/* (except leads POST, health) require auth
- [ ] No secrets in client bundle
- [ ] .env.example committed, .env gitignored
