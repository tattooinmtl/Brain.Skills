# 03 — 高争议团队冲突 Playbook

> 适用问题：**分析团队内部存在实质性分歧，且分歧影响决策质量**。例：政策制定中的派系分歧、并购决策中"买/不买"的对立、战略方向选择、安全事件的"内鬼/外部"归因争议。
>
> **核心模式**：厘清分歧焦点 → 拆解为具体假定 → 用矩阵替代口水战 → 结构化记录剩余分歧。
>
> **来源**：CIA Tradecraft Primer 的"Team A/Team B"传统 + 原书 7.1 对抗性协作 + 7.2 结构化辩论 + ICD 203 的"analysis of alternatives"标准。

---

## 一、何时用本 Playbook

✅ **典型触发条件**（满足 ≥2 条）：
- 团队内出现**两个或更多派系**，分别支持不同结论
- 分歧持续 >1 周，常规会议无法解决
- 分歧影响决策（卡住了，无法推进）
- 一方/双方开始"为立场而战"（адвокат 现象，辩护律师偏见）
- 团队氛围紧张，公开讨论已无效

❌ **不适用**：
- 单纯的信息缺失（先去收集信息，不是结构化分歧问题）
- 权力斗争（不是分析分歧，是政治分歧 → SAT 救不了）
- 时间紧迫（<1 天）—— 直接决策者拍板

---

## 二、何时选 7.1 vs 7.2 vs 6.5/6.6（关键决策）

| 情境 | 推荐 | 理由 |
|---|---|---|
| **2 人或 2 派系明确对立**，愿意合作 | **7.1 对抗性协作** | 结构化地让双方互相陈述对方观点，常导致收敛 |
| **2 派系明确对立**，但 7.1 失败 | **7.2 结构化辩论** | 升级——只驳倒对方论据的规则，第三方仲裁 |
| **团队内"沉默分歧"**（多数同意但少数人有异议不敢说） | **6.1 事前分析 + 6.5 魔鬼代言人** | 仪式化质疑，让异议合法化 |
| **需要系统性挑战整个团队结论** | **6.6 红队** | 独立团队重新分析 |
| **涉及外部专家判断** | **6.7 德尔菲法** | 匿名多轮收敛 |

## 三、4 阶段流程（问题重构 → KAC → ACH → 对抗性协作/辩论）

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│ Stage 1:     │ → │ Stage 2:     │ → │ Stage 3:     │ → │ Stage 4:     │
│ 问题重构     │   │ 把分歧拆成   │   │ 用矩阵替代   │   │ 结构化记录   │
│ (1.4)        │   │ 具体假定     │   │ 口水战       │   │ 剩余分歧     │
│              │   │ (5.1)★       │   │ (4.5)★★     │   │ (7.1 或 7.2) │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘
   30-60 min          1-2 小时            半天-1天            半天-1天
```

### Stage 1 — 问题重构（Issue Redefinition 1.4）

**为什么先做**：很多"分析分歧"其实是**问题定义分歧**。A 派回答的是问题 X，B 派回答的是问题 Y，双方鸡同鸭讲。

**操作**（基于 1.4 问题再定义法）：
1. 让 A、B 双方**各自书面陈述**他们理解的问题是什么。
2. 比较两个陈述 —— 通常会发现分歧根源。
3. 应用 4 种重构策略：
   - **缩小焦点**：把宽泛问题（"X 国是否威胁？"）具体化（"X 国是否在未来 12 个月内对 Y 国发动网络攻击？"）
   - **扩大焦点**：把狭窄问题（"X 部长的言论是否鹰派？"）放到更大背景（"X 国决策圈整体动向？"）
   - **转移焦点**：把无法回答的问题转为可回答的（"对手意图？"→"对手能力与近期行为？"）
   - **颠倒焦点**：把"会不会发生 X"转为"如果 X 发生，会有什么前兆"
4. **达成对问题的共同理解** —— 这是后续一切的基础。**达不成共识，则停止分析，先解决元问题**。

**输出**：一份双方共同认可的问题陈述。

### Stage 2 — 把分歧拆成具体假定（KAC 5.1）

**为什么必做**：模糊的分歧（"我认为是 A""我认为是 B"）无法解决。必须拆解为具体的、可检验的假定。

**操作**：
1. 召集双方 + 中立的**第三方主持人**（关键！）+ 1-2 名局外人。
2. 对共同问题，分别列出：
   - **双方都同意的假定**（共识基础 —— 这部分不需要再争论）
   - **A 派独有的假定**（B 派质疑的）
   - **B 派独有的假定**（A 派质疑的）
   - **双方都未明说的暗藏假定**（最危险，常是真正分歧所在）
3. 扫描触发词："永远""必将""一般而言" —— 暴露暗藏假定。
4. 对每个争议假定执行**四问批判**（5.1 操作步骤）：
   - 我为何确信它正确？
   - 何种情况下它可能不正确？
   - 它过去正确现在是否仍正确？
   - 若它无效，对分析影响多大？
5. 三级归类：基本可靠 / 限定条件下正确 / 关键不确定性。

**输出**：一份结构化的"假定分歧清单"，每个分歧都有明确的可检验陈述。

**关键洞察**：很多分歧在 Stage 2 就解决了 —— 双方发现争议的假定其实可以查证，或发现"我们其实在用不同定义"。

### Stage 3 — 用 ACH 矩阵替代口水战

**为什么用 ACH**：当分歧持续时，口水战已无意义。ACH 矩阵强制双方**把判断从"支持哪个"转为"反驳哪个"**，结构性破除辩护律师偏见。

**操作**（基于 4.5 ACH）：
1. **假设列**：A 派结论 + B 派结论 + 至少 2 个第三方替代假设（如"双方都错了，真相是 C"）。
2. **证据行**：所有双方提到的证据 + 关键假定（来自 Stage 2）+ 缺失证据。
3. **关键**：让 A 派和 B 派**共同评分**矩阵 —— 双方都要为每个单元格打 C/I/NA。
4. **评分分歧本身有诊断价值**：如果 A、B 对同一单元格评分不同，那是**对证据解读的分歧**，而非对结论的分歧 —— 可以进一步追问。
5. 计算**不一致评分** —— 得分最低的假设最可能。
6. **敏感度分析**：如果关键证据被重新解读，结论如何变化？

**常见结果**：
- ✅ ACH 揭示一方假设明显被反驳更多 → 分歧解决
- ✅ ACH 揭示双方假设都有问题 → 共同修改，产生第三种共识
- ⚠️ ACH 显示双方势均力敌 → 进入 Stage 4

**输出**：完整 ACH 矩阵 + 明确的剩余分歧点（哪些证据/假定仍然争议）。

### Stage 4 — 结构化记录剩余分歧（7.1 对抗性协作 或 7.2 结构化辩论）

**何时升级到 Stage 4**：Stage 3 后仍有不可调和的分歧。

#### 选项 A：7.1 对抗性协作（Adversarial Collaboration）

**适用**：双方都有诚意寻求真相，只是观点不同。

**核心规则**（来自原书 7.1）：
1. 双方**书面陈述对方的最强观点**（"钢铁人"步骤 —— 必须证明自己理解对方）。
2. 然后才能批判对方观点。
3. 双方共同撰写**联合报告**，包含：
   - 双方都能接受的结论部分
   - 明确标注的分歧点 + 各自的理由
   - 可观察的"未来指标" —— 哪些事件发生会证明谁对谁错
4. **核心价值**：把"我对你错"的零和博弈转化为"我们共同记录最佳判断"的合作。

#### 选项 B：7.2 结构化辩论（Structured Debate）

**适用**：7.1 失败，或双方已经无法合作。

**核心规则**（来自原书 7.2，关键创新）：
1. **不要求驳倒对方本身，只要求驳倒对方论据** —— 这是与普通辩论的本质区别。
2. 第三方仲裁 + 评判。
3. 双方有平等的时间和资源。
4. 辩论结束后，第三方作出判断或记录不可调和的分歧。

**何时从 7.1 升级到 7.2**：原书 7.2 章节明确指出，"对抗性协作不成功时转用结构化辩论"。

## 四、ICD 203 视角：何时分歧必须上报

> 来源：ODNI ICD 203 *Analytic Standards* (2015)。

ICD 203 的 **Analytic Tradecraft Standard 5(e)(4) — "Incorporates analysis of alternatives"**：

> *"Analysis of alternatives is the systematic evaluation of differing hypotheses to explain events or phenomena, explore near-term outcomes, and imagine possible futures to mitigate surprise and risk."*

**实战含义**：
- 如果分歧涉及**情报产品交付**，ICD 203 **要求**报告呈现替代分析 —— 不能只给一方观点。
- 必须在报告中**明确标注**：哪些是共识？哪些是分歧？分歧的证据基础是什么？
- "Analysis of alternatives" 不是可选的"锦上添花"，是**法定标准**。

## 五、典型时间预算

| 分歧级别 | 总时长 | 推荐流程 |
|---|---|---|
| **轻度**（语义分歧、定义不清） | 1-2 小时 | Stage 1（问题重构）+ Stage 2（KAC）—— 常常这就够了 |
| **中度**（实质观点分歧，可合作） | 1-2 天 | 完整 4 阶段，Stage 4 用 7.1 |
| **重度**（派系对立，无法合作） | 3-5 天 | 完整 4 阶段，Stage 4 用 7.2 + 第三方仲裁 |

## 六、与其他 Playbook 的关系

- **本 playbook 的 Stage 3 (ACH) 与 `01-threat-assessment` Stage 2 共用工具**，但**用法不同**：威胁评估是"穷举外部假设"，本 playbook 是"系统化双方内部假设"。
- **本 playbook 是 7.1 对抗性协作 + 7.2 结构化辩论章节的"应用外壳"** —— 7.1/7.2 章节教你**辩论规则**，本 playbook 教你**把辩论嵌入完整分歧解决流程**。
- **本 playbook = `../cheatsheet.md` §4 "配方 C：高争议问题"的展开版**。

## 七、关键判断法则

1. **Stage 1 是最被低估的**：很多分歧在问题重构阶段就消失 —— 双方发现"我们其实在回答不同问题"。
2. **绝对不要跳过 Stage 2 直接辩论** —— 模糊的"立场分歧"无法辩论，必须先拆为可检验的"假定分歧"。
3. **ACH 矩阵的"评分分歧"是金矿** —— 它揭示了"双方其实在解读同一证据不同"，这比"双方结论不同"更可操作。
4. **Stage 4 的核心不是"决出胜负"，是"结构化记录"** —— 让决策者看到分歧的真实形态，而非双方的修辞。
5. **必要时上报分歧** —— ICD 203 要求呈现替代分析。掩盖分歧是违反 tradecraft 的。
