# 1.2 — AIMS法（AIMS: Audience, Issue, Message, Storyline）

**范式归属**：范式 Ⅳ：结构化协作/流程工具范式
**方法类别**：第一类 分解与可视化
**编号**：1.2

## Core Idea
强制分析人员在起草任何文件之前明确四要素——用户（Audience）、问题（Issue）、信息（Message）、情节（Storyline），避免文件缺乏重点、让读者失望、协调耗时。起草前花一个多小时确定 AIMS，长远可节省大量时间。

## Framework / Mental Model
- **AIMS 四要素模型**：产品构思 = 用户 × 问题 × 信息 × 情节
  - When to use: 撰写任何分析文件之前；主要文件还应在正式的概念文件或职权范围（TOR）中处理
  - How: 依次回答四组问题，得到一份简短清晰的产品构思方案

## Key Concepts
- **Audience（用户）**：主要用户是谁，是高级用户要简短精炼，还是低一级用户要细节长篇
- **Issue（问题）**：目标受众一直困惑或即将面对的关键情报问题
- **Message（信息）**：想传递的核心信息——"电梯演讲"式的一分钟陈述
- **Storyline（情节）**：简单清晰的论证思路，能流畅有逻辑地讲述令人信服的故事
- **多版本策略**：关键用户不止一个时，根据不同用户量身定制不同版本，而非一份文件讨好所有人

## 操作步骤 (Procedure)
1. **用户（Audience）**：确定主要用户。高级用户写简短精炼文章，低一级用户写细节长篇报告。关键用户多个时建议量身定制不同版本，研究撰写前就拟定两份提纲，省略信息保留下来充实第二份。
2. **问题（Issue）**：自问目标受众一直困惑或即将面对的关键问题是什么？他们当前最关注最需要什么？确保问题被密切关注、可操作、有多种回答方式。
3. **信息（Message）**：想向关键用户传递的基本信息是什么？想象电梯里一分钟交谈能表达什么"电梯演讲"。起草前综合成一份简短、清晰、直接的声明。与同事上司讨论文章时记录关键主题或结论，往往易辨出核心信息。
4. **情节（Storyline）**：能否向用户清晰、直接、有说服力地阐述头脑中的基本信息？文章中是否有一个简单清晰的论证思路能流畅逻辑性地讲述令人信服的故事？是否可通过图片视频或其他图形描述故事情节？

## Worked Example
**示意**：分析员要写"某地区恐怖威胁年度评估"。AIMS：A——反恐中心主任（需简短摘要）+ 一线研判员（需详细证据表）→ 两版本；I——"未来12个月最大威胁来自哪类组织"；M——"本土化自激励小团体已超越跨国组织成为首要威胁"；S——按"威胁演变—驱动因素—三类典型—政策建议"的论证链展开。

## 适用场景 (When to Use)
- **何时使用**: 在开始撰写任何分析文件之前使用；对主要文件，还应考虑在更正式的概念文件或职权范围（Terms of Reference, TOR）中处理 AIMS
- **适合的问题类型**: 任何需要撰写分析报告、简报或情报产品的情报任务
- **团队还是个人**: 可单独进行，但小型团队协作效果更佳；将分析工作的上级纳入过程也有帮助
- **预期产出**: 一份清晰的产品构思方案——用户画像、核心问题、关键信息、叙事结构

## 对抗的认知偏见 / 核心价值
作为范式 Ⅳ 流程工具，AIMS 对抗的是**起草冲动**——分析员拿到任务直接动笔而未先想清楚"为谁写、答什么、传什么、怎么讲"。它通过强制四要素显性化，防止文件缺乏重点。更深层的价值在于对抗**取悦所有人的倾向**：当发现关键用户不止一个时，AIMS 强制分析员选择"分版本"而非"塞进一份文件"，避免单一产品无法满足任何一方深层需求。

## 与其他方法的关系
首次开展项目并构思文章时，可配合使用 1.1 启动清单法、1.3 用户清单法、1.4 问题再定义法、1.9 维恩分析法和 2.1 结构化头脑风暴。

## Anti-patterns / 潜在缺陷
- **单一版本讨好所有人**：关键用户不止一个时，仅靠单一版本无法满足所有需求。应当为不同用户准备不同版本，而不是试图用一份文件讨好所有人——这是最常见的失败模式

## Key Takeaways
1. 起草前 1 小时定 AIMS，胜过起草后 10 小时返工
2. 四要素中信息（Message）最难——逼自己写出电梯演讲
3. 多个关键用户 → 多版本，不要折中
4. 情节（Storyline）是论证链，不是章节目录
5. 与上司同事讨论时记录的关键主题，往往就是核心信息

## Connects To
- **1.1 启动清单法**: 启动清单确定"做不做、做什么"，AIMS 确定"怎么做"
- **1.3 用户清单法**: AIMS 的 A（Audience）维度的深化版
- **范式 Ⅳ**: 用流程工具将产品构思显性化，对抗"边写边想"的低效模式
- **电梯演讲（Elevator Pitch）**: Message 步骤直接借用这一商业沟通概念
