# Method Chains — 命名的方法链

> 这是从 55 方法中**外显化**的、值得命名和记忆的"方法链"。每条链都是一个**可复用的微工作流** —— 比 `workflows/*.md` 的 playbook 小，比 `patterns.md` 的模式更具体。
>
> 来源：综合 explore 分析（49 个"与其他方法的关系"段落）+ CIA Tradecraft Primer + Pherson Associates 案例。链名是该 skill 的发明，但链本身有原书或权威依据。

---

## Chain 1: ACH Hub — 6 个家族汇聚到 ACH

**原书原话**（4.5 章）：*"ACH 是本书方法体系的核心枢纽。"*

```
            [上游 — 生成假设/信息]                          [下游 — 验证与监测]
   ┌───────────────────────────────────┐              ┌─────────────────────────┐
   │ 2.1 结构化头脑风暴                │              │ 4.6 论证图示 (深度检验) │
   │ 2.3 名义团体法                    │              │ 6.7 德尔菲 (外部印证)   │
   │ 4.2 多种假设生成™ →               │ ──→ 4.5 ACH ──→ │ 3.6 指标验证因子™      │
   │ 6.7 德尔菲                        │      ★★      │   (未来监测指标)        │
   │ 4.7 欺骗识别 → 欺骗假设           │              └─────────────────────────┘
   │ 5.1 关键假定检查 → 假定作为证据   │
   │ 4.4 诊断推理 → 嵌入评估           │
   └───────────────────────────────────┘
```

**何时用**：任何高风险假设检验（详见 [`workflows/01-threat-assessment.md`](workflows/01-threat-assessment.md)）。

**关键**：ACH 几乎从不孤立使用 —— 它是网络中心节点。单独使用 ACH 的效果存在学术争议（Wilcox & Mandel 2023），但**作为 hub 的链式使用**是被实践证据支持的（Borg PhD thesis）。

## Chain 2: 广角镜 → 显微镜（ACH → Argument Mapping）

**原书原话**（4.6 章）：*"理想的分析流程是先用 ACH 从多个假设中筛选出最站得住脚的那一个，再用论证图示法对该假设的论证结构进行严格检验"* —— ACH = "广角镜"，论证图示 = "显微镜"。

```
4.5 ACH ★★                        4.6 论证图示
─────────────                     ─────────────
广角镜：从 N 个假设中       →      显微镜：对那 1 个最可能假设的
筛出"最少被驳倒"的那 1 个          完整推理链做严格逻辑检验
```

**何时用**：当 ACH 给出了胜出假设，但你需要**对最终结论有最大信心**时（如对外声明、不可逆决策）。

**关键**：这是原书唯一**明确命名的两方法链**。论证图示法把 ACH 的"宏观判断"细化为"每个推理环节的可视化检验"。

## Chain 3: 假定 → 若则检验（KAC → What If?）

**原书原话**（5.1 章）：*"若某假定对分析至关重要但其正确性存疑，可进一步运用'若则分析法'—— 想象该假定不正确时会怎样。"*

```
5.1 关键假定检查 ★               6.3 若则分析法
──────────────────                ──────────────────
识别"关键不确定性"        →       假设该假定不正确，
（既无法证实也无法证伪）           整个分析链如何变化？
```

**何时用**：当 KAC 揭示了无法验证的关键假定时。这是把"假定层面的不确定性"转化为"分析结论层面的敏感度"的标准操作。

**关键**：若则分析 (What If?) 是**侧向思考**（改变一个变量），区别于事前分析 (Premortem) 的**时间视角切换**（假设整体已失败）。

---

## Chain 4: 外部扫描 → 假设生成（Outside-In → Simple Hypothesis）

**原书原话**（5.5 章）：*"先用由表及里思考法充分发掘外部力量，再用简单假设法生成覆盖这些力量的替代假设"*。

```
5.5 由表及里思考                  4.1 简单假设法
─────────────────                 ──────────────────
扫描外部宏观力量           →      为每个力量组合生成假设
（STEEP+2 框架）                   （覆盖外部变量空间）
```

**何时用**：项目启动期，避免"内向视角"（只看组织自身因素）。详见 [`workflows/00-lifecycle.md`](workflows/00-lifecycle.md) Phase 1。

**关键**：5.5 由表及里 + 4.1 简单假设 + 2.1 结构化头脑风暴 是启动期"打破锚定"的标准三件套。

## Chain 5: 启动期四件套（Checklist + AIMS + Brainstorming + KAC）

**来源**：原书 1.1 启动清单章节明确列出："常与 AIMS 法、用户清单法、问题再定义法、结构化头脑风暴、星爆法、思维图示法、维恩分析法、关键假定检查法和多种假设生成法配合使用，在课题启动阶段形成方法组合。"

```
1.1 启动清单 ──→ 1.2 AIMS ──→ 1.4 问题再定义 ──→ 2.1 结构化头脑风暴 ──→ 5.1 关键假定检查
   (12 问)        (产品构思)    (厘清焦点)         (生成替代解释)         (摊定假定)
                                                                                        │
                                                                                        ↓
                                                                              项目正式开始，
                                                                              进入 Stage 2
```

**何时用**：任何新课题启动的前 30-60 分钟。CIA Primer 强调"start early"。

**关键**：这 5 步合计 1 小时投入，能避免数日返工。最被低估的是 1.4 问题再定义 —— 很多项目失败是因为"回答了错误的问题"。

---

## Chain 6: 事前 → 自我批判（Premortem → Structured Self-Critique）

**原书原话**（6.2 章）：*"结构化自我批判法是小型团队或团体用于发现自身分析薄弱环节的一种系统性程序"* —— 是魔鬼代言人的全员进阶版。

```
6.1 事前分析 ★                   6.2 结构化自我批判
─────────────                    ─────────────────
从未来回头看失败          →      系统化追问每个失败假说
（5 分钟，生成失败假说）          （30-60 分钟，10 问批判）
```

**何时用**：定稿前最后一道防线（CIA Primer Phase 3）。事前分析"发现"问题，自我批判"解决"问题 —— 前后承接。

**关键**：事前分析的本质是**仪式化质疑** —— 把"挑刺"包装成"任务角色"，降低社交成本。详见 [`workflows/00-lifecycle.md`](workflows/00-lifecycle.md) Phase 3。

## Chain 7: 维度穷举 → 情景具体化（Morphological → Quadrant Crunching™ → Scenarios）

**原书原话**（2.6 章）：*"形态分析法的具体应用包括象限处理法、多种情景生成法、象限假设生成"*。

```
2.6 形态分析法                   2.7/2.8 象限处理™                3.3/3.4 情景生成
─────────────────                ─────────────────                ─────────────────
列出所有维度与组合       →       选 2 个最不确定维度      →       4 个象限 → 叙事化
（高维穷举）                     画 2×2                            （4-12 个情景）
```

**何时用**：前瞻性预测，不确定性极高。详见 [`workflows/02-early-warning.md`](workflows/02-early-warning.md) Stage 1-2。

**关键**：形态分析是"全空间"，象限处理是"投影到 2D"，情景生成是"为投影点赋予叙事"。三者层层收敛。

## Chain 8: 分歧解决（Problem Redefinition → KAC → ACH → Adversarial Collaboration）

**来源**：原书 7.2 章节明确："对抗性协作不成功时转用结构化辩论"。

```
1.4 问题再定义 → 5.1 关键假定检查 → 4.5 ACH → 7.1 对抗性协作 ──失败──→ 7.2 结构化辩论
   (厘清分歧)     (拆分为可检验假定)   (矩阵替代口水战)  (双方合作)         (第三方仲裁)
```

**何时用**：团队实质分歧，影响决策。详见 [`workflows/03-high-controversy.md`](workflows/03-high-controversy.md)。

**关键**：核心是**把"立场分歧"逐级降维** —— 从"我对你错"到"我们对证据解读不同"到"我们对假定不同"到"我们对问题定义不同"。每一级降维都可能解决分歧。

## Chain 9: 权威压制下的观点生成（NGT → Brainstorming → Voting）

**来源**：原书 2.1, 2.3, 2.4 章节 + CIA Primer 的 Phase 1 强调。

```
沉默头脑风暴 → 名义团体法轮次 → 公开讨论 → 加权排序 (1.7)
(防权威主导)   (轮流陈述)        (此时观点已平等)  (结构化收敛)
```

**何时用**：团队存在权力梯度、专家光环、社交压力时。详见 [`patterns.md`](patterns.md) Pattern 3 匿名轮次。

**关键**：核心是**在观点平等化之后再允许讨论** —— 一旦领导先发言，下属的观点就被锚定。

## Chain 10: 指标定义 → 诊断力验证（Indicators → Indicators Validator™）

**原书原话**（3.6 章）：*"指标验证因子法™ 是指标法的补充升级"*。

```
3.5 指标法 ★                    3.6 指标验证因子™
─────────────                   ─────────────────
为每情景列 5-10 个        →     矩阵化评估每个指标的
"可观察信号"                     诊断力，删除无诊断力者
```

**何时用**：任何预警/监测系统。详见 [`workflows/02-early-warning.md`](workflows/02-early-warning.md) Stage 4-5。

**关键**：未经诊断力验证的指标清单 = 噪音。30 个候选指标常精简到 10-15 个真正有效的核心指标。

---

## Chain 11: 镜像思维破解（Red Hat → Role-Playing → Red Team）

**来源**：原书 5.3 角色扮演与 5.4 红帽、6.6 红队章节的层级关系。

```
5.4 红帽分析 ──→ 5.3 角色扮演 ──→ 6.6 红队分析
(短期会议内)     (持续角色)         (独立团队)
轻量级           中量级             重量级
```

**何时用**：归因涉及**有意图的对手**时 —— 警惕"镜像思维"（假定对手像自己）。详见 [`workflows/01-threat-assessment.md`](workflows/01-threat-assessment.md) Stage 5。

**关键**：投入级别递增。轻量用红帽（5-30 分钟），中量用角色扮演（半天），重量用红队（1-2 周）。

---

## Chain 12: 决策选项评估（SWOT → Force Field → Decision Matrix）

**来源**：原书第 8 类决策支持章节的方法族关系。

```
8.5 SWOT        →    8.4 力场分析      →    8.2 决策矩阵
(战略层面内外因)      (驱动力 vs 阻力)        (多选项 × 多维度加权)
```

**何时用**：需要在多个战略选项之间权衡时（不是假设检验，是决策选择）。

**关键**：SWOT 是"画地图"，力场是"看哪个方向阻力最小"，决策矩阵是"在候选中选最优"。三者层层具体化。

## 综合视图：方法链 vs. Playbook vs. Pattern

| 层级 | 文件 | 粒度 | 例 |
|---|---|---|---|
| **Pattern**（最抽象） | [`patterns.md`](patterns.md) | 跨方法的通用模式（10 个） | "矩阵化诊断"、"证伪倒置" |
| **Chain**（本文件） | 本文件 | 2-5 方法的命名链（12 个） | "广角镜→显微镜"、"ACH Hub" |
| **Playbook**（最具体） | [`workflows/*.md`](workflows/) | 端到端项目流程（4 个） | "威胁评估 5 阶段"、"危机预警 5 阶段" |

**使用顺序**：选 playbook 决定整体流程 → 在 playbook 内部嵌入 chain 作为微工作流 → 每个方法遵循 pattern 的通用法则。
