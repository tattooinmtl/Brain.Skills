# Cheatsheet — 决策指南

> 这不是术语表（那是 `glossary.md`），不是章节摘要（那是 `chapters/`）。这是**作者的判断**：面对 X 类问题时，他会怎么选方法、为什么。每一行帮读者**做决定**。

---

## Section 1: 按"问题类型"选方法（决策树）

```
你的问题是什么类型？
│
├─ 还没开始 / 任务刚到手
│   → 1.1 启动清单 → 1.2 AIMS → 1.4 问题再定义
│   └─ 若团队大：先 1.3 用户清单厘清决策者
│
├─ 信息杂乱、需要整理
│   → 1.5 大事记表（按时间） / 1.6 分类整理（按类别） / 1.8 矩阵（按二维）
│   └─ 若复杂关系：1.9 维恩 / 1.10 网络分析
│
├─ 需要生成新观点 / 替代解释
│   → 团队在场：2.1 结构化头脑风暴
│   → 远程团队：2.2 虚拟头脑风暴
│   → 权威压制严重：2.3 名义团体法
│   → 需要"未知的未知"：2.7 经典象限处理法™
│
├─ 需要预测未来
│   → 单一判断够用：3.1 简单情景
│   → 需要边界：3.2 论点合理性
│   → 需要多情景：3.3 替代前景 / 3.4 多种情景生成
│   → 需要预警监测：3.5 指标法 ★ + 3.6 指标验证因子™
│
├─ 在多个解释/假设之间判断
│   → 简单问题：4.1 简单假设（但要警惕锚定）
│   → 假设不够：4.2 多种假设生成™ / 4.3 象限假设生成
│   → 高风险、不能错：4.5 ACH ★★（旗舰！）
│   → 担心被欺骗：4.7 欺骗识别 + ACH
│
├─ 需要解释因果关系
│   → 先查假定：5.1 关键假定检查 ★
│   → 历史可类比：5.2 结构化类比
│   → 对手视角：5.3 角色扮演 / 5.4 红帽分析
│   → 系统因素：5.5 由表及里思考
│
├─ 怀疑自己的结论
│   → 5 分钟方案：6.1 事前分析 ★（最便宜的质疑工具）
│   → 系统化质疑：6.2 结构化自我批判
│   → 改变关键变量：6.3 若则分析
│   → 寻找黑天鹅：6.4 高影响/低概率分析
│   → 团队分歧大：6.5 魔鬼代言人 / 6.6 红队 ★ / 6.7 德尔菲
│
├─ 团队内部有分歧
│   → 两人对立：7.1 对抗性协作
│   → 团队派系：7.2 结构化辩论
│
└─ 需要在选项之间做决策
    → 简单 Pros/Cons：8.3 PCFF（记得"Fixes"那一步）
    → 多维评估：8.2 决策矩阵 / 8.5 SWOT
    → 力量对比：8.4 力场分析
    → 多利益方：8.6 影响矩阵
    → 复杂动态：8.7 复杂性管理 / 8.1 决策树
```

## Section 4: 跨范式组合 — 4 种典型配方

### 配方 A: "标准情报评估"（最常见的组合）
```
① 1.5 大事记表 + 3.5 指标法          [建立事实基础]
② 4.5 ACH                            [假设检验]
③ 6.1 事前分析                       [决策前 5 分钟质疑]
```

### 配方 B: "战略预警监测"（长期项目）
```
① 1.6 分类整理 + 1.10 网络分析        [信息结构化]
② 3.3 替代前景分析 + 3.4 多种情景     [构建多未来]
③ 3.5 指标法 + 3.6 指标验证因子™      [可监控的预警]
④ 季度复审 + 6.6 红队                 [定期挑战]
```

### 配方 C: "高争议问题"（团队分歧大）
```
① 1.4 问题再定义                      [厘清分歧焦点]
② 5.1 关键假定检查                    [把分歧拆成具体假定]
③ 4.5 ACH                            [用矩阵替代口水战]
④ 7.1 对抗性协作 或 7.2 结构化辩论    [剩余分歧结构化记录]
```

### 配方 D: "极高压、不能错"（如军事情报、并购尽调）
```
① 1.1 启动清单 + 1.2 AIMS             [启动纪律]
② 2.1 结构化头脑风暴 + 4.2 假设生成™  [穷尽假设]
③ 4.7 欺骗识别                        [加入欺骗假设]
④ 4.5 ACH ★★                         [矩阵证伪]
⑤ 6.6 红队分析                        [团队级挑战]
⑥ 6.1 事前分析                        [提交前最后 5 分钟]
⑦ 3.5 指标法                          [交付后持续监测]
```

## Section 5: 关键判断法则（Rules of Thumb）

### 选方法时

- **"重要性 × 不确定性"决定投入深度**：低风险问题不需要 ACH，5 分钟事前分析就够
- **方法不是金科玉律**：原书原话——经验丰富的分析人员"很少会两次都使用完全相同的一种方法"
- **范式多样性 = 分析稳健性**：惯用矩阵评分的人需要补情景想象；惯用实证整理的人需要补假设检验
- **没有 ACH 的高风险判断 = 没做完**：高风险、不能错的问题，ACH 是底线，不是奢侈品

### 使用方法时

- **ACH 的假设必须 MECE**（互斥且穷尽）——否则矩阵结论无效
- **事前分析的失败假说必须具体**——"领导决策失误"是垃圾假说；"X 副总主导的方案因 Y 信息缺失而误判"才是
- **德尔菲法至少 2 轮**——1 轮只是投票，不是收敛
- **SWOT 必须做匹配（S×O / W×O / S×T / W×T）**——只列四象限等于没做
- **关键假定检查的触发词**："永远""必将""一般而言""显然"——这些词出现时，假定就被暴露了
- **指标必须可观察**——"对手内部民意"不是指标；"对手党报头版措辞变化"才是

### 警惕这些"分析异味"（Tells & Smells）

| 异味 | 含义 | 立即行动 |
|---|---|---|
| 团队 5 分钟内一致同意 | 可能是团体迷思，不是真同意 | 强制事前分析或名义团体法 |
| "我们已经考虑了所有可能性" | 几乎肯定没有 | 经典象限处理™ 或形态分析 |
| "这条证据支持我的判断" | 证实偏见已激活 | ACH：改问"反驳哪个？" |
| SWOT 四象限里挤满了 10+ 条 | SWOT 退化为清单 | 删到每象限 ≤3 条，做匹配 |
| 分析报告没有"如果错会怎样" | 计划谬误未受质疑 | 加一段事前分析 |
| 矩阵所有单元格都是 C | 假设可能不互斥 / 证据无诊断力 | 重审假设集 MECE |
| 魔鬼代言人 2 分钟就被说服 | 仪式化反驳（"devil's advocate theatre"） | 改用红队或德尔菲 |
| "我们历史上一直这样做" | 经验主义陷阱 | 结构化类比（5.2）系统比较 |

## Section 6: 高频"旗舰方法"速查卡（必会 6 个）

| # | 方法 | 一句话精髓 | 何时用 | 时间 |
|---|---|---|---|---|
| **4.5** | ACH ★★ | 反转提问：反驳哪个，而非支持哪个；找最少被驳倒的假设 | 高风险假设检验 | 1-2 天 |
| **5.1** | 关键假定检查 ★ | 把暗藏假定摊到桌面逐一质疑，约 1/4 假定经审查被毙 | 分析早期 / 协调会 | 30-60 分钟 |
| **6.1** | 事前分析 ★ | 假设方案已经失败，从未来回溯原因 | 团队达成共识后、定稿前 | **5 分钟** |
| **3.5** | 指标法 ★ | 为每个情景定义可观察的预警信号 | 任何需长期监测的问题 | 半天起 |
| **1.8** | 矩阵法 | 二维表格系统化呈现关系——几乎所有量化方法的载体 | 任何需结构化比较的问题 | 30 分钟起 |
| **2.1** | 结构化头脑风暴 | 匿名书写 → 轮流陈述 → 自由讨论——防权威压制 | 需生成观点 / 假设时 | 1 小时 |

---

**最后的话**：原书强调，"养成结构化思维的习惯比掌握单一方法更宝贵"。本 cheatsheet 不是让你成为 55 种方法的考试专家，而是让你**在对的时刻拿起对的方法**。
